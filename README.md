# F&N

تطبيق Android وiOS للمحادثة والمكالمات الصوتية والفيديو بين حسابين محددين.

- واجهة React Native / Expo.
- رسائل محفوظة على PostgreSQL للنشر عبر الإنترنت، أو SQLite للتطوير المحلي.
- مكالمات WebRTC مباشرة مع إشارات اتصال يتحقق منها الخادم، وبيانات TURN مؤقتة.
- إعادة اتصال عند تغير شبكة الهاتف، ومنع دخول جهازين في الوقت نفسه بالحساب نفسه.

## النشر على Render

ملف `render.yaml` يجهز خدمة Docker على خطة Free، دون قرص مدفوع. تحتاج إلى قاعدة Neon PostgreSQL وخدمة Cloudflare TURN ضمن حدودهما المجانية. راجع [دليل النشر](DEPLOY.md).

اضبط متغيرات الخدمة السرية من لوحة Render:

```text
USER_1
PASSWORD_1
USER_2
PASSWORD_2
DATABASE_URL
CF_TURN_KEY_ID
CF_TURN_API_TOKEN
```

لا تضف كلمات المرور أو عنوان اتصال قاعدة البيانات أو مفاتيح الخدمات إلى Git. ملف `.env.example` يحتوي على أسماء الإعدادات فقط.

تنام خدمة Render المجانية بعد الخمول وقد يتأخر أول اتصال. لا تحفظ SQLite على نظام ملفات الاستضافة المؤقت. تشغيل الخدمة المجانية ليس ضماناً للاستمرار دون انقطاع.

## تشغيل محلي

استخدم Node.js 22.17 أو أحدث، ثم:

```sh
npm ci
```

انسخ `server/.env.example` إلى `server/.env` وحدد الحسابين، ثم شغّل:

```sh
npm run server
```

بيانات SQLite المحلية لا تُرفع إلى Git. ترحيل الرسائل الموجودة إلى PostgreSQL متاح عبر `node server/migrate-sqlite.js` بعد إعداد `DATABASE_URL`.

## بناء تطبيق الموبايل

Expo Go لا يدعم مكتبة WebRTC الأصلية؛ يلزم بناء Android أو iOS أصلي. لبناء نسخة الإنترنت، اضبط عنوان الخادم الفعلي قبل تجميع التطبيق:

```sh
FN_SERVER_URL=https://YOUR-SERVICE.onrender.com
FN_ONLINE_BUILD=1
```

هذه أسماء متغيرات البيئة، وليست أوامر لكل أنواع الـshell. يرفض `app.config.js` عنوان localhost أو HTTP في وضع بناء الإنترنت. شغّل بناء Android باستخدام Android SDK وJava 17، وبناء iOS باستخدام macOS وXcode. على Windows يطبّق `node scripts/prepare-windows-build.js` إصلاح تمرير المسارات في أوامر البناء. يفضل مسار بناء لا يحتوي على رموز خاصة.

ملفات APK المحلية ومفاتيح توقيع النسخة غير موجودة في المستودع. ملفات Android المولّدة مضبوطة للتجربة؛ إعداد اتصال localhost في Android لا يُستخدم لاتصال نسخة الإنترنت HTTPS.

## الاختبارات

```sh
npm run test:server
```

تغطي الاختبارات بقاء الرسائل بعد إعادة تشغيل الخادم، وحصر الحسابات، واستئناف الجلسة، والتحقق من قبول المكالمة، وإصدار بيانات TURN دون كشف مفاتيحها. اختبار الخدمات السحابية الفعلية والمكالمات بين هاتفين مطلوب بعد النشر.

## حدود النسخة الحالية

التطبيق يحتاج أن يكون مفتوحاً لاستقبال المكالمة؛ إشعارات الخلفية والرنين والتطبيق مغلق ليست مضافة. إعداد TURN ضروري لبعض الشبكات. حفظ الرسائل في الخادم لا يوفّر تشفيراً من طرف إلى طرف للرسائل، ويجب حماية الحسابات والخادم وقاعدة البيانات.
